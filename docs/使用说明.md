# 指定号码短信转发工具

自用 Android 应用。安装在 A 手机，精确匹配配置列表中的任意一个发件号码，将短信原文经选定 SIM 卡分别发送到所有目标手机。目标手机无需安装应用。

## 安装与首次设置

1. 将交付的 `sms-relay-1.4.1.apk` 传到 A 手机并安装；按系统提示允许本次 APK 安装。
2. 打开“短信桥”，阅读使用说明，点击“授予必要权限”。需要接收短信、发送短信、电话状态三项权限。
3. 填写实际显示的完整来源号码（可多个，每行一个）、目标号码（也可多个，每行一个），选择发送 SIM 卡，保存。**不要把目标号码填成 A 自己的号码**。
4. 点击“发送测试短信”，核对接收号码和发送 SIM，再确认发送；在各目标手机实际确认收到。
5. 开启“启用自动转发”，用目标平台新发一条短信，核对原文和接收时间。
6. 到 A 手机系统设置允许本应用自启动、后台活动，取消针对本应用的省电限制。菜单随厂商和版本不同；应用内可打开应用设置和电池设置。

必须安装后至少打开一次并完成授权。强行停止后须重新打开；重启后先解锁。A 手机需保持开机、有运营商信号且可正常收发短信，不依赖 Wi-Fi 或移动数据。普通短信按套餐收费，长短信可能按多条计费。

## 1.3.0 多来源、多目标

来源和目标都支持多个号码，各自每行填写一个，也支持英文逗号或中文逗号分隔。来源示例：

```text
+8613800138000
+8613900139000
106123456
```

任何一个来源完整匹配时，都转发到同目标号码（也可多个，每行一个）。号码两端空白和空行会去除，重复来源自动合并，不会因此多发。号码内部不能有空格，`+86` 不会被自动添加或删除。列表中有格式错误的号码时整份配置不保存。

旧版来源和单个目标会继续保留，无需重新配置。仅调整来源/目标顺序或输入分隔符不重置启用时间；实际增删来源或目标并保存，则重新确定新短信接收起点。

每个目标独立记录发送状态和完整正文。某个目标提交失败会继续处理其他目标，失败及未知状态不自动重发。整条接收事件在提交前一次性登记全部目标，重启或调整目标后也不会重放同一条旧事件。若在发送途中崩溃，尚未提交的目标保留未知状态，不自动补发。

测试短信同样发给全部目标，确认框会列出所有号码。**按目标分别收取短信费用**；例如 3 个目标、每条拆成 2 段，可能计费 6 条。

最近 200 条历史按“一个目标一次尝试”计数，例如一条短信转发 3 个目标会产生 3 条记录。旧版本未将当时的目标号写入历史，因此旧记录显示“旧记录未保存目标”，不会用当前目标配置推测历史收件人。

## 升级与短信详情

直接覆盖安装新版，**不要先卸载或清除数据**。新版沿用原签名，升级保留号码、SIM、开关、原发送记录及去重信息。

点击“发送记录”中的任意一条，可查看本次尝试发送的完整短信；长短信可滚动查看，换行与 emoji 保留。详情仅供查看，不表示目标手机已收到，也不会重发。

1.0.0 从未保存正文，所以该版本的旧记录无法补看；1.1.0 起产生的转发和测试记录才有正文。短信内容仅存本机，应用仍禁用云备份和数据迁移备份。

## 规则和状态

- 来源号码完整字符串匹配。不做前缀、包含、后缀、国家码归一化；例如 `106123456` 不匹配 `1061234567` 或 `+86106123456`。
- 任一匹配号码的**所有短信**都转发，包括验证码和非验证码。正文不添加前缀，不提取数字。
- 接收可来自 A 手机任一 SIM；发送只使用保存的 SIM 订阅。失效时不自动改用默认卡，换卡需重新选择并保存。
- 设置修改后需保存。每次重新启用或修改生效规则，以当时本机时间为起点；只处理之后收到的新短信广播，不查询历史短信。
- 关闭开关不撤回已提交到系统的发送任务；测试短信可在自动转发关闭时单独发送。
- **发送成功**：所有分段均收到系统成功回执，不证明目标手机已收到。
- **发送失败**：至少一个分段失败，或提交前检查/提交过程异常。部分分段仍可能已发出。
- **状态未知**：尚未收到完整回执，或进程/系统重启导致回执丢失。不会自动改判成功。
- 失败与未知均不自动重发；查看详情不会触发重发，应用没有历史重发入口。
- 去重先持久化，再提交系统。若恰好在两步之间崩溃，本次可能没有发出，记录保持未知；不以重复收费为代价自动补发。

## 隐私与存储

不申请互联网或历史短信读取权限；不接入服务器、统计 SDK 或云备份。从 1.1.0 起，为支持点击记录查看内容，完整短信正文（可能含验证码）随发送记录保存在本机应用私有数据库中。正文不写入调试日志，不自动复制到剪贴板；用户在详情中可手动选择文字。系统短信应用和运营商仍可能保存发件记录。

本机保存来源号码列表、目标号码列表、发送卡、开关，及最近 200 次按目标分别记录的发送时间、目标号码、卡 ID、分段回执、错误类型和完整正文。超出 200 条时删除最旧记录及对应正文。去重使用 Android Keystore 密钥计算 PDU 的 HMAC 指纹；独立保存指纹，清理旧发送记录不清除去重。清除应用数据或卸载会重置全部配置和去重信息。

## 兼容范围

- 最低 Android 8.0 / API 26；当前 compileSdk、targetSdk 为 35。
- 面向小米安卓系统及仍支持安卓应用的华为设备；没有完成具体机型认证。
- HarmonyOS 5 及以上暂不承诺支持。能安装 APK 或在兼容容器运行，不代表能监听系统短信。
- 系统可能限制或延迟第三方读取验证码，例如带 SMS Retriever 格式的短信，以及新系统中的 WebOTP 保护。厂商也可能有额外限制。安装、普通短信测试成功不代表所有验证码都能及时转发。
- 如果实际来源验证码不能及时触发，判定该机型/系统/短信格式不适用，不绕过系统保护，不声称已支持。

官方参考：[Android 短信接口](https://developer.android.com/reference/android/telephony/SmsManager)、[Android 验证码保护](https://developer.android.com/about/versions/17/behavior-changes-all#sms-otp-protection)、[华为应用安装说明](https://consumer.huawei.com/cn/support/content/zh-cn16061787/)。

## 开发与构建

工具链：JDK 17、Gradle 8.13、Android Gradle Plugin 8.9.2、Kotlin 2.1.20、Android SDK Platform 35 / Build Tools 35.0.0。

1. 安装工具链，在 `local.properties` 中配置 `sdk.dir=/你的/Android/sdk`，或设置 `ANDROID_HOME`。
2. 运行：

```sh
./gradlew testDebugUnitTest lintDebug assembleRelease
```

默认 release 输出为 `app/build/outputs/apk/release/app-release-unsigned.apk`。`scripts/package-local.sh` 将其签名为自用 APK；首次执行会在 `.signing/` 创建本机私有签名材料，后续沿用，以便覆盖升级保留配置。**不要删除或公开 `.signing/`，源码压缩包不包含它。**

```sh
ANDROID_HOME=/你的/Android/sdk scripts/package-local.sh
```

签名后的安装包位于 `dist/sms-relay-1.4.1.apk`。若使用不同签名重新构建，无法直接覆盖旧安装，需要卸载（会丢失应用数据）。

项目本机准备的工具在 `.tools/`；本机使用示例：

```sh
.tools/gradle-8.13/bin/gradle --gradle-user-home .tools/gradle-home testDebugUnitTest lintDebug assembleRelease
ANDROID_HOME="$PWD/.tools/android-sdk" scripts/package-local.sh
```

`.tools/`、构建缓存、本地 SDK 路径和签名材料不属于源码交付。核心代码不依赖 UI；单元测试覆盖规则、发送边界，Robolectric 测试覆盖 SQLite 持久化及基本界面流程。

## 1.4.0 全部短信与界面更新

转发规则新增“转发全部新短信”，默认关闭，升级后仍保留指定来源模式。打开后无需填写来源，任意来源的新短信都会发往全部目标（包含验证码及其他私人短信）。修改开关后点击保存；关闭开关会恢复原来源列表。不会补发历史短信。

界面更新为蓝色状态卡片、分区表单和突出显示的保存按钮。发送记录及正文查看保持可用，不包含隐私模式。全部模式请勿将 A 手机号码填为目标，也不要配置相互转发的设备，避免循环及短信费用。
